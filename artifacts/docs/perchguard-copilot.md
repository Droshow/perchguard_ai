# PerchGuard for GitHub Copilot

PerchGuard intercepts every MCP tool call GitHub Copilot makes — enforcing cost caps, blocking secret bleed, and giving you a live budget meter — before the damage is done.

One command from any project directory. Ctrl-C restores everything.

---

## The problem

Copilot's agent mode fires tool calls continuously: reading files, running shell commands, calling APIs. It has no hard spending limit. Its usage meter on github.com shows you yesterday's damage, not what is happening right now. One runaway loop in an afternoon session can cost more than your monthly budget.

PerchGuard sits between Copilot and your MCP tool server. Every call passes through a policy engine before it executes. If a session is burning through tokens faster than expected, PerchGuard terminates it at the moment the limit is crossed.

---

## What it protects against

| Threat | How PerchGuard stops it |
|---|---|
| **Runaway cost loops** | Session terminates when estimated spend hits `maxCostPerSessionUSD` |
| **Token budget overrun** | Hard cap at `maxTokensPerSession` |
| **Spin loops** | Rate-limits tool calls to `maxToolCallsPerMinute` |
| **Secret bleed** | Blocks calls forwarding `.env`, API keys, or credentials |
| **Prompt injection** | Detects injections in files Copilot reads (poisoned README, malicious dependency) |
| **Destructive shell flags** | Strips `--force`, `--no-verify`, `-rf` from command parameters |
| **Unauthorised tools** | Per-role allowlist — only `read_file`, `write_file`, `search_files` allowed by default |
| **Path traversal** | Blocks `../../../etc/passwd` patterns in file arguments |

## Prerequisites

- Go 1.23+
- GitHub Copilot with MCP agent mode enabled (VS Code ≥ 1.99)
- An MCP tool server already configured in `.vscode/mcp.json`

---

## Install

```bash
git clone https://github.com/Droshow/PerchGuard.git
cd PerchGuard/perchguard
bash scripts/install.sh
```

This builds the binary and installs it to `~/.local/bin/perchguard` (or `/usr/local/bin` with `--system`). It also installs the default policy files to `~/.config/perchguard/` — the binary finds them automatically from any directory.

Verify:

```bash
perchguard --help
```

## Quick start

### Step 1 — Run `--mode=wrap` from your project

```bash
cd ~/Work/my-project
perchguard --mode=wrap
```

**First time with no `.vscode/mcp.json`?** PerchGuard creates a template for you:

```
Created: /home/user/Work/my-project/.vscode/mcp.json

Edit the file above:
• For an HTTP MCP server: set the correct URL under 'my-http-server'.
• For a stdio MCP server: set command + args under 'my-stdio-server'.
• Delete the example that doesn't apply.
Then re-run:  perchguard --mode=wrap
```

The template covers both server types:

```json
{
  "servers": {
    "my-http-server": {
      "url": "http://localhost:3000"
    },
    "my-stdio-server": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "/path/to/workspace"]
    }
  }
}
```

Edit it with your real MCP server details, delete the unused example, then re-run `perchguard --mode=wrap`.

## Browser dashboard

When PerchGuard is started with `--mode=copilot`, a browser dashboard starts automatically on `:8081` alongside the stdio MCP proxy.

```
[perchguard] copilot dashboard → http://localhost:8081
```

Open the URL in any browser. The page auto-refreshes every 3 seconds with no browser extension or page reload needed.

### Panels

| Panel | Data source | What it shows |
|---|---|---|
| **Session Budget** | `/api/sessions/{id}/budget` | Token / cost / call progress bars, colour-coded green → yellow → red |
| **Active Policies** | `/api/pipeline` | Every validator, mutator, and quota as a badge with a green dot; enforcement mode and policy hash |
| **Decisions** | `/api/stats` | `ALLOW` / `DENY` / `MUTATE` / `TERMINATE` / `HUMAN_REVIEW` counts |
| **Top Blocked Tools** | `/api/stats` | Top-5 tools by denial count from the audit ring |

The dashboard routes are **unauthenticated** — they bind to their own `http.ServeMux` on a separate port (`:8081`) that you should not expose beyond localhost.

### Changing the port or disabling the dashboard

```bash
# different port
perchguard --mode=copilot --dashboard-addr :9191

# or via env var
PERCHGUARD_DASHBOARD_ADDR=:9191 perchguard --mode=copilot

# disable entirely
PERCHGUARD_DASHBOARD_ADDR="" perchguard --mode=copilot
```

The dashboard only starts in `--mode=copilot`. In `--mode=wrap` use the terminal meter instead, or run `--mode=copilot` directly and skip the auto-patching.

## How `--mode=wrap` works

`--mode=wrap` does three things automatically:

1. **Reads** `.vscode/mcp.json` (walks up the directory tree to find it)
2. **Patches** it — HTTP servers have their URL rewritten to `http://localhost:8080/mcp`; stdio servers are rewritten to launch `perchguard --mode=mcp-proxy` with the original command stored in env vars
3. **Starts** the PerchGuard HTTP server (admission controller + management API)

On exit (Ctrl-C, kill, or normal termination) the original file is restored.

### HTTP server wrapping

```
Before:  Copilot → http://localhost:3000
After:   Copilot → http://localhost:8080/mcp → PerchGuard → http://localhost:3000
```

### stdio server wrapping

```
Before:  VS Code spawns → npx -y @modelcontextprotocol/server-filesystem /path
After:   VS Code spawns → perchguard --mode=mcp-proxy → npx ... (as subprocess)
```

Each `perchguard --mode=mcp-proxy` instance is an independent stdio proxy. It enforces the same policy and writes to the same audit log.

## Policy

The default Copilot policy is installed at `~/.config/perchguard/copilot-profile.yaml`. It is pre-configured for developer use: cost controls on, autonomous-agent features (fleet analysis, semantic firewall) off.

### Default limits

```yaml
sessionBudget:
  limits:
    maxTokensPerSession: 500000      # ~$1.50 at Claude Sonnet pricing
    maxCostPerSessionUSD: 5.00       # hard USD cap
    maxToolCallsPerSession: 200
    maxToolCallsPerMinute: 30
    idleTimeoutMinutes: 15
    maxDurationMinutes: 120
  action: TERMINATE_SESSION
```

Edit `~/.config/perchguard/copilot-profile.yaml` to change limits. Changes take effect within 30 seconds — no restart needed.

To use a project-specific policy instead:

```bash
PERCHGUARD_POLICY=./my-policy.yaml perchguard --mode=wrap
```

### Tool allowlist

By default the `developer_agent` role may only call `read_file`, `write_file`, and `search_files`. This blocks `run_command`, `list_dir`, and any custom tools unless explicitly allowed.

To expand the allowlist, edit the `toolAuthorization` section in the policy file:

```yaml
toolAuthorization:
  enabled: true
  roles:
    - name: developer_agent
      allowedTools:
        - read_file
        - write_file
        - search_files
        - run_command    # add this to allow shell execution
```

### What is enabled vs disabled

**On** (matters even with a developer present):

| Policy | Reason |
|---|---|
| `sessionBudget` | Runaway loops burn money regardless of who is watching |
| `promptInjection` | Malicious content in files Copilot reads can redirect the session |
| `dataExfiltration` | Copilot reading `.env` and forwarding it is a real attack path |
| `toolAuthorization` | Allowlist which tools Copilot may call |
| `parameterSanitization` | Strips `--force`, `--no-verify`, `-rf` from shell commands |
| `leastPrivilege` | Blocks path traversal in file arguments |
| `outputValidation` | Redacts injected instructions in tool outputs |
| `audit` | Full JSONL trail for every call |

**Off** (unnecessary with a developer at the keyboard):

| Policy | Reason |
|---|---|
| `agentFleet` | One developer, one session — drift scoring is noise |
| `semanticFirewall` | Adds LLM latency; the developer can interrupt in real time |
| `humanReview` | The developer *is* the human reviewer |
| `depthLimiter` | Copilot does not spawn sub-agents |

## Management API

The API key is auto-generated at startup and printed in the first log line. Pass it with `Authorization: Bearer <key>` or set `PERCHGUARD_API_KEY` before starting.

| Endpoint | Description |
|---|---|
| `GET /healthz` | Health check (no auth required) |
| `GET /api/sessions` | Active sessions |
| `GET /api/sessions/{id}/budget` | Live budget snapshot |
| `GET /api/audit?limit=N` | Recent tool call decisions |
| `GET /api/stats` | Decision counts, top denied tools |
| `DELETE /api/sessions/{id}` | Terminate a session immediately |

Example — check what just got blocked:

```bash
API_KEY=pgmk-...   # from startup log

curl -s -H "Authorization: Bearer $API_KEY" \
  "http://localhost:8080/api/audit?limit=5" | jq '.[] | {tool, decision, reason}'
```

## Audit trail

Every tool call is appended to `snapshots/audit.jsonl` in the directory where PerchGuard was started:

```json
{"timestamp":"2026-05-27T15:10:42Z","session_id":"pg-1748352600","tool":"read_file","decision":"ALLOW","reason":"all checks passed","estimated_tokens":87}
{"timestamp":"2026-05-27T15:10:43Z","session_id":"pg-1748352600","tool":"run_command","decision":"DENY","reason":"Tool 'run_command' is not in the allow list for role 'developer_agent'"}
```

On session termination a governance record is written to `snapshots/governance.json` with the full call history, decision counts, and final budget state.

## Environment variables

| Variable | Default | Description |
|---|---|---|
| `PERCHGUARD_POLICY` | `~/.config/perchguard/copilot-profile.yaml` | Policy file path (auto-discovered) |
| `PERCHGUARD_MCP_UPSTREAM` | *(from mcp.json)* | HTTP MCP upstream URL — `wrap` sets this automatically |
| `PERCHGUARD_GOVERNED_MODEL` | — | Model Copilot is using; drives cost estimation |
| `PERCHGUARD_ADDR` | `:8080` | Listen address |
| `PERCHGUARD_API_KEY` | auto-generated | Management API bearer key |
| `PERCHGUARD_AGENT_ROLE` | `developer_agent` | Role matched against `toolAuthorization` policy |
| `PERCHGUARD_DASHBOARD_ADDR` | `:8081` (copilot mode) | Browser dashboard address. Set to `""` to disable. |
| `PERCHGUARD_TLS_CERT` / `_KEY` | — | Enable HTTPS |

Policy discovery order (first match wins):
1. `PERCHGUARD_POLICY` env var
2. `~/.config/perchguard/copilot-profile.yaml` (installed by `scripts/install.sh`)
3. `<binary-dir>/../configs/copilot-profile.yaml` (running from the repo)
4. `./configs/copilot-profile.yaml` (CWD fallback)

## Token cost estimation

PerchGuard estimates tokens from MCP payload size (byte-length ÷ 4) and prices the result using a built-in model rate table. Set `PERCHGUARD_GOVERNED_MODEL` for accurate pricing:

```bash
export PERCHGUARD_GOVERNED_MODEL=claude-sonnet-4-6
```

Supported models (May 2026):

| Model | Input / M tokens | Output / M tokens |
|---|---|---|
| `claude-opus-4-7` | $15.00 | $75.00 |
| `claude-sonnet-4-6` | $3.00 | $15.00 |
| `claude-haiku-4-5` | $0.80 | $4.00 |
| `gpt-4o` | $5.00 | $15.00 |
| `gpt-4o-mini` | $0.15 | $0.60 |
| `gemini-2.5-pro` | $3.50 | $10.50 |
| `gemini-2.5-flash` | $0.30 | $2.50 |

Unknown models fall back to $5.00 / $15.00 per million tokens (conservative).

## Troubleshooting

**`perchguard --mode=wrap` fails with "no policy file found"**

Run `bash scripts/install.sh` from the repo root — this installs the default policies to `~/.config/perchguard/`. Or set `PERCHGUARD_POLICY` explicitly.

**PerchGuard is not intercepting calls**

Confirm `.vscode/mcp.json` now points to `http://localhost:8080/mcp`. Run `perchguard --mode=wrap` again if the file was manually edited after patching. Verify the proxy is up: `curl http://localhost:8080/healthz`.

**Budget meter shows "No active sessions"**

Sessions appear after the first tool call in a Copilot agent task. Start a task that triggers a file read or search, then refresh the meter.

**A tool call was blocked unexpectedly**

Check the audit log: `cat snapshots/audit.jsonl | tail -5 | jq .reason`. The most common cause is the tool not being in the role's allowlist. Add it to `toolAuthorization.roles[developer_agent].allowedTools` in the policy file.

**Session terminated mid-task**

A budget limit was reached. The final audit entry has `decision: TERMINATE_SESSION` and the reason. Raise the limit in `~/.config/perchguard/copilot-profile.yaml` — it hot-reloads within 30 seconds.

**`.vscode/mcp.json` was left patched after a crash**

Run `perchguard --mode=wrap` again — it will detect the already-patched URL (pointing to `:8080`) and re-patch correctly. Or manually restore the original URL. The original is always the URL you set before running wrap.

**Browser dashboard shows no data / blank panels**

The dashboard only starts in `--mode=copilot`, not `--mode=wrap`. Verify the URL is `http://localhost:8081` (or whatever `PERCHGUARD_DASHBOARD_ADDR` is set to) and that PerchGuard started without errors. If the port is already in use, set `--dashboard-addr :9191` to use a different one.

**Dashboard port conflicts with another service**

Set `--dashboard-addr :9191` (or any free port). The management API on `:8080` is unaffected.
